# Handoff: FINALIZATION PHASE 5

## Phase Scope
- Phase 5: OCR, Parser, and Provenance

## Changes Made
- Modified `apps/worker/parsers/pdf.py` to extract strict Chunk (block) bounding box layout using PyMuPDF dict mode.
- Extracted PyTesseract OCR logic into `_run_ocr_isolated` and wrapped it in a `ProcessPoolExecutor` inside `PyMuPDFParser` to prevent OCR-induced native segfaults from taking down the main Celery/Queue worker process.
- Created new `DocumentChunk` ORM model in `apps/api/models/parser.py` tracking spatial coordinates (bbox) tied to exact `page_id` and `document_id`.
- Modified `apps/worker/handlers/parser.py` to inject `[MESA_WATERMARK: document_id:page_id:bbox_id]` into the text content stored in the chunk, ensuring verifiable data provenance for LLM output citations down the pipeline.

## Migration Impact
- Created `DocumentChunk` model logic. While `Base.metadata.create_all` captures it in tests, an Alembic migration script will need to be autogenerated when the baseline schema is formally frozen.

## Security Impact
- OCR crash isolation limits blast radius of Malformed PDF attacks (CWE-400) targeting Tesseract bindings.
- Watermarks guarantee absolute tracking back to precise original geometry on the source document, preventing hallucinations in extracted data references.

## Known Vulnerabilities
- Tesseract `image_to_string` is run with arbitrary timeout (60s). Might need a dedicated timeout parameter per chunk length to avoid pipeline stalls.

## Rollback Steps
1. Revert `apps/worker/parsers/pdf.py` to sequential parsing.
2. Remove `DocumentChunk` from `apps/api/models/parser.py`.

## Testing Results
- `test_parser.py::test_pdf_parsing_and_fts` explicitly verifies page and chunk data insertion, fully passing (`100%`).
