# WO-003 — Shared Backend Foundation

## Amaç
API ve Worker uygulamaları için ortak kullanılacak temel backend altyapısının (veritabanı bağlantısı, konfigürasyon, hata yönetimi, izlenebilirlik, UUIDv7 ve audit taban modeli) kurulması.

## Ön koşullar
- WO-002 (Core Docker profili) tamamlanmış olmalı. Postgres servisi çalışır durumda olmalı.

## İzin verilen repo ve yollar
- `apps/api` (özellikle core modülleri)
- `apps/worker`
- Kök dizindeki `pyproject.toml` (gerekli bağımlılıkları eklemek için)

## Yasak yollar
- Frontend tarafı (`apps/web`)

## Değiştirilecek sözleşmeler
- `apps/api/core` dizini altına ortak altyapı kodları yerleştirilecektir.
- Veritabanı modeli olarak SQLAlchemy (v2.0 stili) ve göç (migration) aracı olarak Alembic kullanılacaktır.
- Hatalar RFC 7807 (problem+json) standardına göre döndürülecektir.

## Uygulama adımları
1. **Bağımlılıklar:** `fastapi`, `pydantic-settings`, `sqlalchemy`, `alembic`, `psycopg`, `uuid7` (veya `uuid-utils`) paketleri eklenecektir.
2. **Config Precedence:** Ortam değişkenlerinden yapılandırma okuyacak Pydantic BaseSettings modeli oluşturulacaktır.
3. **UTC Clock:** Zamanı her zaman UTC olarak dönen soyut bir utility yazılacaktır.
4. **UUIDv7:** Birincil anahtarlar ve request ID'ler için UUIDv7 üreten yardımcı fonksiyon eklenecektir.
5. **Trace/Correlation Middleware:** Gelen isteklerde (varsa) Trace ID/Correlation ID alan, yoksa UUIDv7 ile yeni üreten ve log bağlamına ekleyen middleware oluşturulacaktır.
6. **Problem+Json Handler:** Global exception handler ile FastAPI hataları ve uygulama hataları RFC 7807 formatına çevrilecektir.
7. **SQLAlchemy & Alembic:** Async session (veya sync, planın detaylarına göre; MESA FastAPI kullandığı için async session tercih edilebilir ama plana göre ayarlanacak) ve Alembic altyapısı kurulacaktır.
8. **Audit Base:** `created_at`, `updated_at`, `created_by`, `updated_by` ve `version_id` (optimistic locking için) alanlarını içeren SQLAlchemy base class'ı (Base) yazılacaktır.
9. **Idempotency Store:** İsteğin idempotent işlenmesini sağlayacak tablo ve mekanizma kurulacaktır.
10. **Testler:** Gerçek PostgreSQL üzerinde çalışacak entegrasyon testleri (hata envelope kontrolü ve idempotency testleri) eklenecektir.

## Kabul kriterleri
- Gerçek PostgreSQL üzerinde integration testler geçiyor mu?
- Hata envelope (problem+json) test ediliyor mu?
- Idempotency conflict durumu test ediliyor mu?

## Çalıştırılacak testler
- `make test` (pytest fixture'ları ile PostgreSQL'de geçici bir db açılarak veya test db üzerinde çalışacak şekilde ayarlanacak).

## Güvenlik/veri kontrolü
- Veritabanı bağlantı dizesi loglanmamalıdır.
- Güvenlik açığı yaratacak exception traceback'leri 500 hatalarında gizlenmelidir.

## Rollback
- Gerekirse ilgili dosyalar ve db tabloları drop edilebilir.
