# WO-011 — Review, approval ve solo mode

## Amaç
AI veya sistem tarafından üretilen verilerin doğrudan güvenilir (verified) kabul edilmesini engelleyen, insan (avukat) onayını merkeze alan bir inceleme (review) ve onay (approval) kuyruğu oluşturmak.

## Ön Koşullar
WO-010 tamamlandı.

## İzin verilen yollar
- `apps/api/models/review.py`
- `apps/api/routers/reviews.py`
- `apps/api/main.py`
- `alembic/versions/`

## Yasak yollar
- `Desktop/MESA`

## Uygulama Adımları
1. **Veritabanı Modelleri (`apps/api/models/review.py`)**:
   - `ReviewQueue`: İnceleme bekleyen öğeler (`entity_type`, `entity_id`, `status: pending, approved, rejected, corrected`).
   - `AuditLog`: Onay/Red işlemlerinin değişmez (immutable) kayıtları.
2. **Kısıtlamalar & Politikalar (Policy Engine)**:
   - "AI kaydı doğrudan verified olamaz" kuralının veritabanı seviyesinde default status = 'pending_review' olarak tanımlanması.
   - Solo mode için "cooling-off" mekanizması (örneğin, approval yapıldığında external_use_state'in belirli bir süre gecikmeli aktif olması).
3. **API Uç Noktaları (`apps/api/routers/reviews.py`)**:
   - `GET /reviews`: Bekleyen incelemeleri getir.
   - `POST /reviews/{id}/approve`
   - `POST /reviews/{id}/reject`
   - `POST /reviews/{id}/correct`
4. **Veritabanı Migration**: Yeni tablolar için Alembic migration oluşturulması.

## Kabul Kriterleri
- AI kaydı doğrudan verified olamaz.
- Onay veya red işlemleri Audit log tablosuna eklenir ve değiştirilemez.

## Çalıştırılacak Testler
- Yeni API endpoint'lerinin test edilmesi (mock veriler ile FastAPI Swagger veya curl).
