Sen, MESA Law repository’sini mevcut kabataslak MVP seviyesinden:

```text

# 3. Kesin ürün hedefi

Sistem aşağıdaki gerçek kullanıcı akışını desteklemelidir:

```text
Kullanıcı Keycloak/OIDC ile giriş yapar
→ Yetkili olduğu hukuk bürosunu seçer
→ Matter/dosya oluşturur
→ Matter üyelerini ve rollerini yönetir
→ PDF, DOCX veya TXT belge yükler
→ Belge immutable storage alanına alınır
→ Hash, MIME ve malware kontrolü yapılır
→ Dijital parsing veya Türkçe OCR çalışır
→ Sayfa/paragraf/source locator verisi oluşur
→ Hukuki veri önerileri çıkarılır
→ Öneriler Review Center’a düşer
→ Avukat onayladığında canonical veriye dönüşür
→ Timeline oluşturulur
→ İddia, savunma ve delil ilişkileri gösterilir
→ Kullanıcı matter içinde kaynaklı soru sorar
→ Sistem yalnız yetkili ve işlenmiş kaynaklardan cevap verir
→ Hukuk kaynakları aranır
→ Potansiyel süreler tespit edilir
→ Avukat süreyi doğrular
→ Kaynaklı taslak hazırlanır
→ Taslak revision’ları saklanır
→ Citation’lar doğrulanır
→ Dış kullanım onayı olmadan export yapılamaz
→ Her kritik işlem audit edilir
```

# 4. Değiştirilemez mimari kararlar

## 4.1 MESA Core sınırı

MESA Core ayrı repository olarak kalacaktır.

Yapma:

* MESA Core kodunu MESA Law içine kopyalama.
* MESA Law hukuk domain sınıflarını MESA Core’a ekleme.
* MESA Core repository’sine kullanıcı onayı olmadan yazma.
* MESA’yı canonical hukuk veri kaynağı yapma.

MESA entegrasyonu yalnız aşağıdaki portlar üzerinden yürümelidir:

```text
MesaIntelligencePort
MesaIngestionPort
MesaV4HttpAdapter
```

MESA erişilemezse normal matter ve belge yönetimi çalışmaya devam etmelidir.

## 4.2 Canonical veri sahipliği

```text
PostgreSQL
= kullanıcı, firma, membership, matter, belge metadata,
  review, canonical hukuk verisi, deadline, draft,
  notification, audit ve operasyon kayıtları

S3 / MinIO
= orijinal ve türetilmiş immutable dosyalar

MESA
= yeniden üretilebilir vector, graph, assertion ve memory projection
```

MESA’nın bütün verisi PostgreSQL ve object storage’dan yeniden üretilebilmelidir.

## 4.3 Runtime entegrasyonu

Ürün runtime’ı:

```text
MESA Law Backend
→ versioned HTTP/REST adapter
→ MESA V4
```

kullanmalıdır.

MCP yalnız geliştirici agentler içindir. Son kullanıcı runtime’ında MCP kullanılmamalıdır.

## 4.4 Teknoloji sınırları

Backend:

* Python,
* FastAPI,
* Pydantic,
* SQLAlchemy 2,
* Alembic,
* PostgreSQL.

Frontend:

* Next.js App Router,
* React,
* TypeScript,
* TanStack Query,
* React Hook Form,
* Zod,
* Orval-generated API client.

Worker:

* PostgreSQL durable job queue,
* `FOR UPDATE SKIP LOCKED`,
* lease,
* retry,
* dead-letter.

İlk sürümde Celery veya RQ ekleme.

Redis yalnız ephemeral cache, fan-out veya geçici bildirim için kullanılabilir.

# 10. Faz 4 — Belge ingestion güvenliği

Gerçek state machine:

```text
UPLOAD_INTENT_CREATED
UPLOADING
UPLOADED
VERIFYING
QUARANTINED
SCANNING
CLEAN
INFECTED
PARSING
OCR_REQUIRED
OCR_RUNNING
PARSED
EXTRACTION_PENDING
READY
FAILED
BLOCKED
MANUAL_REVIEW_REQUIRED
```

Finalize sırasında:

1. Object gerçekten var mı kontrol et.
2. Object key beklenen tenant/matter/revision altında mı kontrol et.
3. Boyutu doğrula.
4. SHA-256 hesapla.
5. MIME sniffing yap.
6. Uzantı–MIME eşleşmesini kontrol et.
7. Duplicate kontrolü yap.
8. ZIP bomb ve nested archive kontrolü yap.
9. PDF aktif içerik risklerini kontrol et.
10. Karantinaya al.
11. ClamAV scan job oluştur.
12. Operation kaydı oluştur.
13. Outbox event üret.

Object key:

```text
tenant_id/matter_id/document_id/document_revision_id/original.<extension>
```

formatında olmalıdır.

Original object immutable olmalıdır.

MinIO bucket:

* private,
* anonymous access kapalı,
* versioning açık veya immutable key zorunlu,
* presigned download yetki kontrollü.

* path traversal protection,
* SQL injection regression,
* XSS regression,
* default secret validation.
